# jj-hunk v0.5.1

Hunksets now use operation-first functions with named path, file, and content conditions. Pattern modifiers replace the separate regex functions.

```bash
jj-hunk list --query 'added(path:glob:"src/**" | glob:"tests/**", content:regex:"timeout|deadline")'
jj-hunk split --query 'added(content:"timeout")' "fix: increase request timeout"
```

## Paths versus files

```text
added(path:glob:"src/**", content:"timeout")
added(file:glob:"src/**", content:"timeout")
```

The first selects added-text blocks in existing source files and matching whole new files. The second selects only whole new source files. `removed(...)` has the corresponding removed-text and whole-file deletion behavior. There is no `kind` argument.

Empty files can match `file:`. Binary file additions/deletions also match `file:`, but their contents are not searched as text. Matching text in a new file selects the whole file; matching text in an existing file selects the whole edit block, including both sides of a replacement.

Use `added(file:glob:"**", content:exact:"")` to select empty new text files. A missing text side does not match an empty pattern.

```text
renamed(from:glob:"src/**", to:glob:"archive/**")
mode_changed(path:glob:"scripts/**")
```

## Migration from 0.5.0

This release changes query syntax despite the patch version. Update saved queries and `[hunkset-aliases]` definitions. Old spellings are not retained as compatibility aliases.

| 0.5.0 | 0.5.1 |
|-------|-------|
| `content("timeout")` | `changed(content:"timeout")` |
| `added_text("timeout")` | `added(content:"timeout")` |
| `removed_text("timeout")` | `removed(content:"timeout")` |
| `regex("timeout.*")` | `changed(content:regex:"timeout.*")` |
| `added_regex("timeout.*")` | `added(content:regex:"timeout.*")` |
| `removed_regex("timeout.*")` | `removed(content:regex:"timeout.*")` |
| `glob("src/**")` | `changed(path:glob:"src/**")` |
| `before_glob("src/**")` | `changed(before_path:glob:"src/**")` |
| `after_glob("src/**")` | `changed(after_path:glob:"src/**")` |
| `added()` (whole-file additions) | `added(file:glob:"**")` |
| `deleted()` | `removed(file:glob:"**")` |
| `renames()` | `renamed()` |
| `modes()` | `mode_changed()` |
| `binaries()` | `binary_changed()` |

`added()` without arguments now includes text additions and replacements with added text, as well as whole-file additions. `removed()` includes blocks with removed text and whole-file deletions. `changed()` selects all change units. `all()`, `none()`, and exact `id(...)` selection are unchanged.

The JSON/YAML spec format, whole-block selection rules, and comparison-bound ID encoding are unchanged. Alias arguments remain set expressions. Invalid patterns or arguments fail before mutation; valid empty query selections remain no-ops.
